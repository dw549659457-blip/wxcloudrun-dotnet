# 小程序与适老交互验收

## 已完成的本地自动检查

- TypeScript 严格检查、ESLint、原生 JS 打包；12 个页面和2个组件的注册文件齐全。
- 数量用 decimal.js 与字符串，0、负数、超精度及包装小数拒绝；同单位准确合计。
- 原生 Page 控制器与 wx.request 适配器调用真实 .NET + MySQL：1000 个包装、派发100、消耗70、最终回收25、损耗5，仓库925；12箱蔬菜正常出库3、手工出库1后剩8；服务器对账一致。
- 模拟提交已成功但响应丢失、查询也不可用：显示待确认，保留原 key/body；人工再确认不会重复出库。
- 多开放批次不静默选择；下一笔数量为空；包装选择仅来自当前派发批次；另司机不可读取批次，装菜员不可读全局包装库存。
- 本机草稿按员工隔离，切换账号清除；首次绑定控制器的手机号拒绝、候选确认、“不是我”和协助路径使用接口替身测试，不能视为线上微信验收。
- 正文固定18px，主按钮20px/56px，数量更大，独立点击区域48px，间距8px以上，底部安全区、输入 cursor-spacing。源码布局没有为窄屏缩小字号。

没有实际微信开发者工具或真机凭证，本地 Node 控制器测试不验证微信渲染、授权资格、callContainer 网络或键盘表现。Web 管理端浏览器320/375/1440宽度已自动检查；微信以下检查仍待人工逐项记录。
