# 1.2.2角色名称与职级说明

职级为：管理员（ADMIN）→后台管理员（原会计，ACCOUNTANT）→司机、女工/工人、出库员。

仅修改角色显示名称，原角色标识、账号、密码与已有业务权限配置均保留，不批量修改人员姓名。已有005/006的业务库不需要新增SQL。

| 功能 | 管理员 | 后台管理员 |
| --- | --- | --- |
| 下级员工建档、修改、岗位分配、启用/停用、解绑 | 允许 | 允许 |
| 下级员工微信开通批准/拒绝 | 允许 | 允许；批准后仍需员工本人确认 |
| 创建/修改同级或上级后台账号，修改后台密码 | 允许 | 禁止 |
| 原有数据与报表查询、导出、其他业务操作 | 全部允许 | 保留已有配置；默认查询导出，写操作按配置 |
| 权限配置、操作日志和变更审计查询 | 允许 | 禁止 |

后台管理员的人事权限仅适用于WEB_ADMIN后台登录，不给小程序ACCOUNTANT会话追加权限。员工查询users.read为人员管理固定职责，不可撤销；其他配置项仍可调整。角色只能分配系统现有的下级岗位，不能创建新的角色类型。

不能通过把后台账号先降为工人、停用同级、混合选择ADMIN/ACCOUNTANT或直接调用接口绕过职级限制。后台密码由最高管理员维护；将普通员工升为后台账号时须设置独立密码。人员写入事务会重新检查操作者当前角色与启用状态。

人员管理与审批继续记录请求日志和业务变更审计，管理员可在“管理审计”查询操作人、时间、角色、结果及前后差异。密码和凭证不进入审计内容。

管理员新增后台管理员：员工与角色→新增员工→勾选后台管理员→设置独立密码→保存。原会计账号无需重建，可使用原账号密码登录。

后台管理员新增下级员工：员工与角色→新增员工→填写本人姓名、唯一账号和手机号→选择司机、工人或出库员→保存。不得选择管理员或后台管理员。

后台管理员审批：开通协助审批→线下核实本人→选择启用且未绑定的下级员工→填写原因→批准。员工在本人微信确认后才获得小程序会话。

交付的1.2.2工程包包含此说明及数据维护填写表。1.2.1图文手册作为历史资料保留，其中原“会计”及人员管理范围以本说明为准。
