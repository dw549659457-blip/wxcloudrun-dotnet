# 后台验收记录

## 本地实测

环境：Debian x64、.NET SDK10.0.401/ASP.NET10.0.12、MySQL8.0.45（真实InnoDB），独立随机测试库，开发库vegetable_dev；用户生产库未访问。

运行`dotnet test tests/Business.Tests.csproj`，37项测试通过（32项业务/认证/数据库维护集成测试、3项云托管配置及2项启动进程用例），0失败、0跳过。包括：

- 1000包装->下发100->消耗70/产出70->部分回收10/实收40->最终回收15/实收28->损耗5->正常出库50->DIRECT10，最终包装925、蔬菜8、差异2。
- 多棚户独立关闭、重复包装合并、一种不足整单回滚。
- 两个女工并发消耗、两笔并发出库，真实独立MySQL连接、库存不负。
- 同key并发只生成一单，改payload冲突，失败key可重试；两个应用实例共享幂等。
- 关闭后作业/重复最终回收拒绝、实收超过产出有原因地记录负差异。
- 正数量/公斤3位/箱整数、零负与超精度拒绝。
- 草稿不入账、版本冲突、提交后不得编辑。
- 冲销与重建保留旧单/审计、依赖阻止冲销、重建失败原单及余额完整恢复。
- 跨月损耗分母、完整筛选Excel、防公式、单位/实际正量/展示负量。
- 角色和对象归属、公网伪造微信头、未知字段、未经认证导出拒绝、CSRF。
- 微信首次确认/协助批准/解绑流程使用独立FakeWechat，真实接口尚未联调。
- 账号停用与角色变更撤销旧会话；重建应用实例后会话和库存仍存在。
- 空库迁移、重复迁移、历史名称快照、只读余额/流水/产出对账。
- 生产root默认拒绝，显式MYSQL_ALLOW_ROOT=true后正确读取注入的地址、账号、密码与库名，开发登录保持关闭。
- 显式建库命令重复执行保留现有账号和迁移记录，拒绝系统库、原示例库及不安全库名。
- 生产缺MYSQL_DATABASE或root开关时，独立dotnet进程退出1并记录STARTUP_FAILED，不再由未处理异常SIGABRT退出。

`database/wechat-cloudrun-init.sql` 已在本地随机隔离库中完整导入：业务表、写锁行和4条迁移校验记录正确，无示例账号；应用迁移接受该结构并跳过已执行文件；重复导入拒绝非空库且原表/校验记录不变。验证结束删除该随机测试库，未连接用户提供的内网数据库。

源码Build与Release publish本地已通过，锁定NuGet还原通过。最新发布输出还通过真实HTTP闭环（库存925/8、对账一致）。手工备份脚本和隔离恢复脚本已本地执行，恢复后的库存925/8、7张有效单据与账本对账一致；恢复脚本拒绝非空库并验证业务表确实导入。最终执行结果以本次交付记录为准；如果增加测试需要同步更新计数。
